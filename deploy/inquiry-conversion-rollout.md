# 询盘成功转化切换

这次修复需要主题代码、GTM 容器和 Google Ads 配置一起完成。仅部署主题不会停止现有 GTM 按钮点击误报；仅发布新 GTM 而主题未部署会漏记新询盘。先准备未发布工作区，主题通过 PR 审查并部署后立即发布对应容器版本，再执行下方生产验收。

## 主题与事件契约

- 三个 AJAX 表单只有在询盘及附件成功保存后，才从响应的 `data.inquiry` 取得 `conversion_id` 和 `form_context`。邮件失败但询盘已保存仍算有效线索。
- 前端发送 `event: inquiry_success`、`inquiry_id` 和 `form_context`（`full` / `product` / `quick`）。`inquiry_id` 为服务端 HMAC，既可去重又不暴露后台自增编号。不得把邮箱、姓名、电话、留言或附件名加到此事件里。
- 同一页面内相同凭据只上报一次；成功页加载、刷新和浏览器返回均不补报。普通表单最多等待 1200 ms 的 GTM 回调后跳转，快速询盘立即显示原位成功反馈。统计被拦截时业务仍成功。
- 无 JavaScript 的 POST 路径仍可按原有配置工作，但不产生浏览器成功事件；不能通过成功页浏览量补算。
